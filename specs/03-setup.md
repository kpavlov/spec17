# Setup: install and doctor

- **SETUP-01** MUST — `install` writes the skill to `<repo>/.agents/skills/spec17` and merges a spec17 entry into `.mcp.json`, keeping every other server and key.
- **SETUP-02** MUST — leave a `.mcp.json` that is not valid JSON untouched.
- **SETUP-03** MUST — `uninstall` removes only what `install` added, and deletes `.mcp.json` only if install created it.
- **SETUP-04** MUST — only read the global MCP config (`~/.claude.json`), never write it. (manual)
- **SETUP-05** MUST — `doctor` only reads: unless asked with `--fix`, it never runs `codegraph init` or `codegraph sync` and never writes files.
- **SETUP-06** SHOULD — `doctor` fails only when spec17 cannot run at all (no repo, an unreadable `spec17.json`); no specs is a warning with a hint (a sample requirement line and the folder names), and every other check still runs.
- **SETUP-07** MUST — build or refresh the CodeGraph index only when the user asks (`doctor --fix`, the Settings tab buttons, the dashboard's rescan button): `init` only when there is no index, `sync` only when there is one, and never automatically: not from a check, a startup, a push or a timed reload.
- **SETUP-08** SHOULD — `codegraph` takes `action=refresh`: run `sync` whenever an index exists and the binary is on PATH, also while a codegraph process runs (a running MCP server can have its file watcher off, `serve --mcp --no-watch`, and then never updates the index; `sync` beside one is safe, codegraph's own lock reports a busy index and nothing is forced); otherwise do nothing and say why.
- **SETUP-09** SHOULD — `doctor` tells how to install CodeGraph when its binary is missing (the installer commands and the docs link; spec17 never installs it) and judges the index's freshness from its last write against the newest source or test file, whether or not a codegraph process runs: older means a warning that names `sync`.
- **SETUP-10** SHOULD — `install` with `server=codegraph` adds the `codegraph` MCP entry (`{"type":"stdio","command":"codegraph","args":["serve","--mcp"],"alwaysLoad":true}`, what `codegraph install --print-config claude` prints) to `<repo>/.mcp.json`: the file is created if missing, other servers and keys are kept, an existing `codegraph` entry is never overwritten, and invalid JSON is left untouched (SETUP-02); `uninstall` with `server=codegraph` removes only that entry (customised or not, since the user asked), keeps the other servers, and deletes the file only when nothing else is left (SETUP-03), leaving the skill and the spec17 entry alone; `install_status` says whether the repo, and the global config (read-only), has it.
- **SETUP-11** SHOULD — the installed skill tells the agent to write or change the requirement before the tests and the code, and, when code or tests changed so that a requirement no longer matches, to show the user the requirement, what the code does now and the proposed wording, and to edit the requirement only after the user confirms: never silently, never by weakening a level to fit the code. (manual)
- **SETUP-12** MUST — `uninstall` accepts `only=skill|mcp` (`--only skill|mcp` in the CLI) for the project or global scope. Skill removal deletes only the files install wrote (`spec17/SKILL.md`, `spec17/references/*.md`) and the folders that leaves empty. MCP removal deletes only `mcpServers.spec17`, including a customised entry, from the selected `.mcp.json` (`<repo>/.mcp.json` or `~/.mcp.json`), preserving other keys and servers and leaving invalid JSON untouched. `install_status` reports the entry in each `.mcp.json`; `~/.claude.json` remains read-only (SETUP-04).
- **SETUP-13** MUST — `spec17 install` installs the skill and HTTP MCP in the chosen scope, including with `--global`. The setup tools can install or remove just the skill or one MCP transport in either scope. In each `.mcp.json`, HTTP uses `mcpServers.spec17` and stdio uses `mcpServers.spec17-stdio`, so either entry can be installed or removed independently. The stdio entry starts spec17 with `--stdio-mcp --no-http-mcp --no-ui`, targeting the repo for a project install and using the client's working directory for a global install. `install_status` reports each transport separately.
- **SETUP-14** MUST — `install_status` returns the configured loopback `/mcp` URL for a spec17 HTTP entry and the executable and arguments for a spec17 stdio launcher written by Setup, in both scopes. Missing entries have no connection details. Arbitrary custom arguments, credentials and environment variables are omitted from the status response.
