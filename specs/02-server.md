# Server: CLI, API and MCP

- **API-01** MUST — define every tool once in `server/src/ops.rs`, so the CLI and `/mcp` return the same answer; the dashboard calls them over `/mcp`, with no second HTTP API for them.
- **API-02** MUST — bind 127.0.0.1 only and answer 403 to an unknown `Host` or `Origin` on `/api` and `/mcp` (DNS rebinding).
- **API-03** MUST — read spec, test and source files only by names the scanner itself lists, so `..` and absolute paths are rejected.
- **API-04** MUST — serve MCP over streamable HTTP at `/mcp`, with the dashboard as the one `ui://spec17/dashboard` resource, which only the `dashboard` tool opens; its optional `view` (`modules`, `requirements/DOC-25?state=none`, …) picks the page, and `dashboard` returns the URL with it.
- **API-07** SHOULD — offer the modules and detected test cases as read-only JSON MCP resources, `spec17://modules` and `spec17://tests`, and search tools beside them: `search_modules` filters by path and changed files; `search_tests` filters by module, tagged state, text and changed files. Label tests detected, not run. `/mcp` also answers the 2026-07-28 revision (per-request `_meta`, no `initialize`, `server/discover`) so the dashboard reads them with the MCP client SDK.
- **API-08** SHOULD — offer the report, status, uncovered and overlap views as plain-text MCP resources (`spec17://report`, `spec17://status`, `spec17://uncovered`, `spec17://overlap`) beside their tools, which stay for clients without resource support, and accept `subscriptions/listen` for the `spec17://` resources: acknowledge only the URIs it has, send `notifications/resources/updated` for them within about 2 seconds of a change to the repo's files or the CodeGraph index, and end the stream when the client cancels or the server shuts down.
- **API-09** SHOULD — declare an `outputSchema` (JSON Schema) on every tool, typed from the same structs the result is serialized from, so a client can validate and read the tool's `structuredContent`.
- **API-10** SHOULD — offer each of the report, status, uncovered and overlap views also as a JSON resource (`spec17://report.json` and so on, the tool's `structuredContent`), beside the text resource and the `modules` and `tests` JSON resources. Every JSON resource names the JSON Schema that types it, in its description and in `_meta.schema`, and that schema is itself readable at `spec17://schemas/<name>` (`application/schema+json`).
- **API-11** SHOULD — offer `module` (WRITES FILES) with `path` and `hidden`: `hidden=true` appends a module's folder (one the modules view lists, not the repo root) as an anchored line to the repo's `.spec17ignore`, keeping what is there, so the next scan leaves it out (SCAN-15). It is for the user's action in the dashboard, never run on its own.
- **API-12** SHOULD — list the modules hidden that way (the anchored folder lines of `.spec17ignore`) as `hidden` in the modules view, and let `module` with `hidden=false` remove such a module's line from `.spec17ignore`, keeping every other line, so the next scan lists it again. It refuses a path that is not in `hidden`.
- **API-13** SHOULD — offer `changes`, `diff` and `history` (SCAN-18..20: `ref`, `commit`, `staged`, `include_untracked`, `ignore_whitespace`, `show_ignored`, `show_all`; against HEAD and with untracked files by default) and the `staged`, `include_untracked` and `ignore_whitespace` filters of `status`, also as the `spec17://changes` resource (text and `.json`, pushed when the repo changes, which includes staging and committing); without git it says "not checked".
- **API-15** SHOULD — offer `commits` (SCAN-30): `{commits: {ID: {sha, short, author, date, subject}}}`, one line `ID short date author subject` per requirement in the text; needs git.
- **API-16** SHOULD — offer `blame` (SCAN-31) with `path` and `lines`: `{path, lines: {N: {sha, short, author, date, subject}}}`; needs git.
- **API-17** MUST — list every tool of `ops::tools()` in the tool table of `skills/spec17/SKILL.md`, so an agent that reads the skill knows all of them.
- **API-18** MUST — annotate read-only MCP tools with `readOnlyHint: true` and tools that write files with `readOnlyHint: false`, so clients can distinguish them.
- **API-14** MUST — run the CLI's `report`, `status`, `trace`, `overlap` and `uncovered` through the same tools as MCP, with the same text (`--json`: the tool's `structuredContent`, except that `overlap --json` prints the rows list and the CLI's `status` lists every row), and offer `changes`, `diff` and `history` as CLI commands with the tools' filters (`--ref`, `--commit`, `--staged`, `--no-untracked`, `--ignore-whitespace`, `--show-ignored`, `--show-all`).
- **API-05** MAY — move the dashboard and `/api/info` to a separate `--ui-port`, which also carries `/mcp` for the dashboard, while the main port carries only `/mcp`.
- **API-06** MUST — serve the embedded dashboard from release builds, falling back to `index.html` for client-side routes.
- **API-19** SHOULD — accept an optional `requirement_id` in `search_tests` that matches the full ID of a test tag case-insensitively and combines with the other filters (API-07).
- **API-20** SHOULD — offer a read-only `search_requirements` tool for a scanned, repo-relative `test_file`. With no line, return the known requirements tagged anywhere in the file. With a 1-based `line`, return the known requirements tagged on the detected test with the greatest start line at or before `line`; an optional inclusive `end_line` also includes tests starting after `line` through `end_line`. A nearest untagged test contributes no IDs.
- **API-21** SHOULD — on startup, `spec17` and `spec17 serve` print a banner with the name, version and copyright to stderr before the workspace and endpoint information. Not with `--stdio-mcp` (API-23). (manual)
- **API-22** MUST — `spec17` and `spec17 serve` accept `--stdio-mcp` to expose the same MCP tools and resources on stdin and stdout. `--no-ui` disables the web dashboard and `/api/info` and skips opening a browser. `--no-http-mcp` disables streamable HTTP MCP on every port. The three flags together bind no TCP listener and let independent agent sessions run on the same host. With none of the flags, the dashboard and HTTP MCP remain enabled by default.
- **API-23** MUST — with `--stdio-mcp`, the process writes no log output to stdout or stderr: neither the banner and workspace, endpoint and setup lines (API-21) nor errors, so a client reading the stdio stream or capturing logs sees only MCP traffic. A failure ends the process with a non-zero exit code.
- **API-24** SHOULD — identify the MCP server as `spec17`, with the crate version and the Cargo `homepage` (`https://spec17.dev`) as `websiteUrl`, in the `initialize` result's `serverInfo`, not as the MCP library.
- **API-25** MUST — expose the embedded spec17 skill over HTTP and stdio using the MCP Skills extension: advertise it, list and retrieve its complete metadata and file manifest, and serve the same `SKILL.md` bytes at `skill://spec17/SKILL.md` as a Markdown resource. Unknown skill URIs return invalid params.
