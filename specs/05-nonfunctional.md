# Non-functional: CI and deployment

How spec17 is built, tested and shipped. These describe the workflows under `.github/`, which no Rust test exercises, so each ends `(manual)`: the evidence is the workflow file and its runs.

- **NFR-01** MUST — CI (`.github/workflows/ci.yml`, on pull requests and manual dispatch) runs `pnpm run check` and `cargo test --workspace --locked` in debug and in release (the release run covers the embedded-UI test), from the frozen lockfiles. (manual)
- **NFR-02** MUST — release builds start only by manual dispatch of `.github/workflows/prerelease.yml`, with a required `tag`. They build linux-x86_64, linux-aarch64 and windows-x86_64, each on a native runner (no cross-compiling or emulation), one job per target, and a failed job does not cancel the others. (manual)
- **NFR-03** MUST — a dispatch with a `tag` builds that existing tag and refuses, before building anything, unless the tag is `v<workspace version>` or `v<workspace version>-<suffix>`. (manual)
- **NFR-04** MUST — a tag build goes into a GitHub prerelease: it is created if missing, an existing prerelease only receives assets (assets of the same name are replaced); the workflow never promotes it or edits its notes. Another pipeline (the macOS archives built locally) can add to the same release in any order, and uploading to a finalized release fails. Promotion to a release is manual and follows tap generation. (manual)
- **NFR-05** SHOULD — `make release-dev` builds on Apple Silicon from a clean HEAD equal to `origin/main` and uploads a uniquely versioned Mac archive and checksum to the rolling prerelease `edge`. Its distribution tag points to the built commit, and its notes name that commit. (manual)
- **NFR-06** MUST — name each archive `spec17-<version>-<os>-<arch>.tar.gz` (`.zip` on Windows), where `<version>` is the workspace version for a tagged release and `dev.<UTC timestamp>` for a dev build. Put the binary (`spec17`, `spec17.exe`) at the archive root and a `<archive>.sha256` beside it. (manual)
- **NFR-07** MUST — build the web UI once, from `web/pnpm-lock.yaml`, before the Rust build, and build Rust with `--locked`; the shipped binary embeds the UI and needs no Node, pnpm or Rust at runtime. (manual)
- **NFR-08** SHOULD — run `--version` on each built binary before packaging it. Tagged builds show the workspace version. `make release-dev` embeds and checks `<workspace version>-dev+<short commit hash> (<UTC build timestamp>)`. (manual)
- **NFR-09** MUST — `prerelease.yml` and `tap.yml` use only the default `GITHUB_TOKEN` with `contents: write`, no other secret. (manual)
- **NFR-10** SHOULD — manually dispatch `.github/workflows/tap.yml` with the version tag while the release is still a prerelease. It verifies the two Linux archives, Windows ZIP and at least one native Mac archive against their checksums, then generates `Formula/spec17.rb` and commits it to the default branch. (manual)
- **NFR-11** SHOULD — the formula has a block for each archive the release holds (macOS and Linux, arm64 and x86_64) and none for the ones it lacks; its download URL is the plain release URL when the repository is public, and the API asset URL with `HOMEBREW_GITHUB_API_TOKEN` when it is private. (manual)
- **NFR-12** SHOULD — `make dist` writes the archive and its `.sha256`, after signing the binary on macOS (`make sign`: ad hoc, or `SIGN_IDENTITY`). `make upload` and `make release-dev` build before touching GitHub and upload to the corresponding prerelease under NFR-03 to NFR-06. Promotion is manual. (manual)
- **NFR-13** SHOULD — the tap contains `Formula/spec17.rb` with a standard `head` block before the first tagged release. `brew install --HEAD` checks out the default branch, builds `web/` from the frozen lockfile, and installs the `server` crate with `SKIP_WEB_BUILD=1`. Node, pnpm and Rust are build dependencies of the `head` block only. Tap generation updates the stable release block and preserves HEAD support. (manual)
- **NFR-14** SHOULD — after uploading a dev archive, `make release-dev` writes `Formula/spec17-dev.rb` for the maintainer to publish. Homebrew checks the archive checksum and installs the Apple Silicon binary directly. The formula version increases with the UTC build timestamp so `brew upgrade` picks up subsequent publishes. (manual)
- **NFR-15** SHOULD — `.github/workflows/pages.yml` builds the Hugo site in `docs/` with a pinned Hugo and deploys it to GitHub Pages on a push to the default branch that changes `docs/`, and on manual dispatch. It uses only the default `GITHUB_TOKEN` with `pages: write` and `id-token: write`; the base URL comes from the platform. `make docs` builds the same site locally into `docs/public`. (manual)
- **NFR-16** SHOULD — the docs site is static and searches locally: Hugo writes `index.json` (title, URL and plain text of each page) and a small script in `docs/static/` queries it in the browser, with no external service or CDN, so it also works under `make site`. Google Analytics and Google Tag Manager scripts are allowed on the docs site, only as NFR-19 describes, and never in the dashboard (`web/`). (manual)
- **NFR-17** SHOULD — every HTML page on the docs site ends with a footer centered below the content column, with an evidence reminder, copyright credit, a Contact IT Staff link, a GitHub feedback link, links to the privacy and cookie policies, and, when analytics is configured, a Cookie settings button. (manual)
- **NFR-18** SHOULD — docs screenshots open in a lightbox that fills most of the screen and matches the active theme. Use `+` and `-` to zoom, drag or scroll to pan, and press Escape or click again to close it. (manual)
- **NFR-19** MUST — the docs site loads Google Analytics (Hugo’s embedded `google_analytics.html` partial, `services.googleAnalytics.id` in `docs/hugo.toml`) and Google Tag Manager (`params.gtm`) only after the visitor accepts analytics; with both IDs empty there is no analytics code and no banner. Until then the partial’s output stays inert in a `<template>`. Google Consent Mode v2 defaults `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` to denied; accepting grants `analytics_storage` alone. There is no `<noscript>` iframe. (manual)
- **NFR-20** MUST — the consent banner names the controller, the purpose and Google as the recipient, says how to withdraw, offers Accept and Reject with equal prominence, does not block the page, and remembers the choice in the browser for 12 months. The footer’s Cookie settings button reopens it; withdrawing consent removes the `_ga` cookies and reloads the page without Google scripts, in every open tab. When the choice cannot be saved, no earlier acceptance is reused, a rejection still holds in that tab after a reload (session storage) and still reaches the other open tabs. (manual)
- **NFR-21** SHOULD — the docs site has a privacy policy and a cookie policy page, linked from the footer and the consent banner and left out of the page list, pager, search index and `llms*.txt`. (manual)
