# AGENTS.md

spec17: Rust workspace (`core`, `server`) + Svelte dashboard (`web`) + the agent skill (`skills/spec17/SKILL.md`, embedded in the binary by `server/src/skill.rs`). See README.md for usage.

## Commands

- `cargo test --workspace` (debug) and `SKIP_WEB_BUILD=1 cargo test --release --workspace` (the embedded-UI test runs only in release; needs `web/dist`)
- `make parity` (optional) compares with the old Python scripts if they are vendored in `ROOT/.agents/skills/spec-driven`; the scripts are no longer in this repo.
- `cd web && pnpm run build && pnpm run check`
- `make dev` / `make run`; override `ROOT`, `PORT`, `OPEN=0`
- `make notices` regenerates `NOTICES` (`scripts/notices.mjs`: crates for the release targets via `cargo metadata`, npm packages actually bundled into `web/dist`); run it after dependency changes. Release archives ship it with `LICENSE`.
- Colours, fonts and radius are shared: `docs/static/tokens.css` is the one copy (`light-dark()` pairs, `data-theme` override; tone ramp, shadow and control tokens (`--btn-*`, `--input-pad`, `--focus-ring`) too; `docs/static/syntax.css` maps code colours onto them); `web/src/tokens.css` is a symlink to it (Hugo drops a static symlink that points outside `docs/`, so the real file lives there). Change the palette there, not in `web/src/app.css` or `docs/static/style.css`.
- Docs screenshots: `make screenshots` (`scripts/screenshots.mjs`, needs Chrome) breaks `specs/02-server.md`, `server/src/main.rs` and `server/src/ops.rs` on purpose, captures every `docs/static/img/*.png` through headless Chrome, then `git checkout`s those files (it refuses to run if they have uncommitted changes); update its `breakThings` if those anchors move. Reference `img/name.png` in markdown; if `static/img/name-light.png` and `name-dark.png` both exist, `docs/layouts/_markup/render-image.html` emits both and `style.css` shows the one for the theme, else the file as written.
- `make docs` builds the Hugo site (`docs/`, no theme, `layouts/all.html`) into `docs/public`; `.github/workflows/pages.yml` deploys it. Doc pages follow the same rules: evidence, not truth. Agent docs: `llms.txt`, `llms-full.txt` and a `.md` twin of every page (`docs/layouts/home.llms*.txt`, `page.markdown.md`, output formats in `hugo.toml`).

## Rules

- **Evidence, not truth.** Tool descriptions, UI and docs must not claim a requirement is implemented or a test passes. No LLM in the core.
- Output is deterministic: same tree, same text. Text renderers in `core/src/report.rs` kept the Python output byte for byte; changing them changes what `SKILL.md` describes, so update it too.
- **All SQL lives in `core/src/codegraph.rs`**, read-only (`SQLITE_OPEN_READ_ONLY`). Schema drift is a typed `SchemaDrift` error rendered as "not checked", never a panic. A missing index is not an error either: indexing is the user's decision.
- Tools are defined once in `server/src/ops.rs`; the CLI and `/mcp` both go through it, and the dashboard calls `/mcp` too (there is no separate tool API under `/api`, which keeps only `/api/info`). Add a tool there, not per interface.
- `Analysis` uses `Rc` (not `Send`): run it inside `spawn_blocking`.
- The server binds 127.0.0.1 only; the Host/Origin guard in `server/src/main.rs` covers `/api` and `/mcp` (DNS-rebinding). Don't loosen it.
- Web: plain Svelte + Vite, no SvelteKit, pnpm (no npm, no Bun; `packageManager` in `web/package.json` pins it). `vite-plugin-singlefile` output must stay one `index.html`: it is embedded and also served as the MCP Apps resource. `web/src/lib/transport.ts` is the only place that knows fetch vs MCP Apps bridge. Layout: `src/lib/ui` (generic components), `lib/layout` (split/preview state), `lib/requirements` (level + state badges, ID link), `lib/views` (diff, graph); logic modules (`tone`, `router`, `transport`, …) sit in `lib/`; import across folders with `$lib/…` (alias in `vite.config.ts` and `tsconfig.json`). Level and state tones, labels and hints live in `lib/tone.ts`; show them with `LevelPill`/`StatePill` (or `RequirementBadges`, the pair), never ad-hoc pills; level words inside `{@html}` markdown become `LevelPill`s through `{@attach levelPills(html)}`.
- No hardcoded layout: empty `spec17.json` fields are detected in `core/src/detect.rs` (a table of ecosystem profiles, specs folder names, CodeGraph file list via `Graph::file_paths`, else a walk). Ecosystem profiles (extensions, comments, declarations, tests, test-case markers) live in `core/resources/profiles.toml`: support a new language by adding a `[[profile]]` there, no Rust change. Requirement-line patterns (ID, level, check mark, bullet/table and heading/paragraph openers) live in `core/resources/spec_format.toml`; block-end rules stay in `scan::block_end`. `core/test-data/` holds one small repo per spec layout (left out of the dogfood scan by `.spec17ignore`); add a case there when a new format is supported. All walking goes through `detect::walk`: symlinks only into the root or `ALLOWED_PATHS`; keep every file listing on it. `detect::Ignore` (`.aiignore`, `.spec17ignore`, built-in `.agents`) is applied in `walk` and to the CodeGraph file list and module data; a new listing of graph files must filter with `Project::ignored`. Rust inline tests make auto-detected `tests` include `src`, so pin `tests` when doc examples look like tags.

- `spec17 install/uninstall` (`server/src/skill.rs`): `.mcp.json` is merged, never rewritten wholesale (keep `serde_json` `preserve_order`; other servers stay; invalid JSON is left alone). Only the skill files install wrote (`SKILL.md`, `references/*.md`, listed in `skill::FILES`) and the folders left empty are removed. Edit `skills/spec17/` to change the skill: each file is `include_str!`-ed; a new reference file goes into `FILES`. The same install logic backs the CLI, the `spec_install*` tools and the dashboard Settings tab (`skill::apply`/`status`); global MCP config (`~/.claude.json`) is only read, never written. The server's workspace is resolved once at startup (`Project::open`), not per request. A repo with no specs is not an error of `Project::open` (zero requirements; doctor warns); no repo at all still is.

- `spec17 doctor` (`server/src/doctor.rs`) `run` only reads. The one writer is `doctor::index` (`codegraph init`/`sync`), reached only by an explicit user action: `doctor --fix`, `spec_codegraph`, the Settings tab buttons (with a confirm), the dashboard's ↻ rescan (`action=refresh`: `sync` whenever an index exists, also beside a running codegraph, whose watcher can be off; do not gate it on a process probe). Never call it from a check, a startup path or a scan. Add new checks to `run`; the CLI, `spec_doctor` and the Settings tab share it.

- Spec places (`core/src/detect.rs::spec_paths`): a specs folder, single files (`SPEC.md`), any markdown with a requirement line as a last resort; `Spec.file` is repo-root-relative. `[ID](x.md)` links and decision folders give `ref` docs (`Project::docs`): never due.

- **Dogfooding.** `specs/*.md` are this repo's requirements (`SCAN-`, `GRAPH-`, `API-`, `SETUP-`, `WEB-`, `NFR-` for CI and deployment, all `(manual)`), configured by `spec17.json` for Rust. A Rust test is tagged with `#[doc = "[API-02]"]` above its `#[test]` (a `// [ID]` comment would count as comment-only); code cites with `// (API-02)`. Fixture tags in tests must not look real: write `[DEM\x2D01]`. Run `make report`; new behaviour gets a spec bullet first.

## Sandbox notes

Port binding may be blocked (EPERM); `make dev` then cannot run in-session. Server behaviour is covered by in-process tests in `server/src/main.rs` (`tower::ServiceExt::oneshot`). Use `CARGO_HOME`/`npm_config_cache`/`pnpm --store-dir` in the scratchpad if `~/.cargo` is read-only.
